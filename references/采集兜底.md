# 采集兜底手册（直连失败时才读）


> 📁 **路径约定（V1.6）**：本文件的 `out/`、`state/`、`data/raw/` 均指数据根目录（默认 `~/WorkBuddy/scm-collector-data/`，可用环境变量 SCM_DATA_HOME 覆盖）下的相对路径，非 skill 代码目录。
> 适用场景：直连采集整系统失败（批量404/结构变化/持续超时）、收割器连不上浏览器调试端口、或需要排查接口改版。日常主路径是直连，**不要**为提速走本手册。
> **V1.8（2026-11-05）浏览器底座已切换**：chrome-devtools MCP 已移除，采集浏览器 = 比特浏览器 `suyi` 专用窗口（无代理直连），页面级操作 = 裸 CDP（`scripts/cdp.mjs` / `cdp-eval.mjs`，零依赖）。本文所有「take_snapshot / evaluate_script / MCP请求文件」旧操作均有对应替代，见各节。

## 附A：凭据兜底（收割器连不上调试端口时）

> 适用：fetch 报「未发现任何Chrome DevTools端口」或比特分支未命中（比特客户端未运行/窗口缺失/API key失效）。V1.8 起按下列顺序排查，请求文件导入仅作最后回落。

```
1. 比特客户端在运行吗？（未运行 → 请用户启动比特浏览器，Local API 默认 54345）
2. API key 有效吗？（报「token 失效/Login out」→ 比特「系统设置→Local API」重新复制 Token，
   更新 ~/.workbuddy/mcp.json 的 bitbrowser.headers.x-api-key；脚本自动读取该文件）
3. suyi 窗口存在吗？（node scripts/bit.mjs --no-open 找不到 → 比特MCP browser-create 或用户手动创建）
4. 窗口开着吗？（check-login.mjs 会幂等拉起；仍失败 → node scripts/cdp-eval.mjs --list 看 CDP 是否可达）
5. 以上都通但收割仍失败 → 登录态本身有问题，走【登录阻断流程】让用户在窗口里重新登录
```

**请求文件导入兜底（历史手段，仅当上述全失败且窗口 CDP 可达时）**：用 cdp-eval 直接从页面收割替代网络请求文件——

```bash
# 衣者：直读 storage（快路径，与 harvest-auth storageScan 同逻辑）
node scripts/cdp-eval.mjs --system yizhe --out creds-yizhe.json \
  --js 'JSON.stringify(Object.assign({},...Object.entries({...localStorage}).filter(([k,v])=>v.includes("token")).map(([k,v])=>({[k]:JSON.parse(v)}))))'
# 多客：key 在 IndexedDB（新版前端 localStorage 为空，keyval-store 库 keyval 表 duoke:app 键，zustand persist 双重JSON，取 state.token）
node scripts/cdp-eval.mjs --system duoke --out creds-duoke.json \
  --js '(async()=>{const db=await new Promise((res,rej)=>{const r=indexedDB.open("keyval-store");r.onsuccess=()=>res(r.result);r.onerror=()=>rej(r.error)});const tx=db.transaction("keyval","readonly");const st=tx.objectStore("keyval");const v=await new Promise((res)=>{const q=st.get("duoke:app");q.onsuccess=()=>res(q.result)});return JSON.stringify(v)})()'
# 然后按下方 JSON 结构写入 state/auth.json 后重跑第1步（fetch 收割不可达时自动用缓存）
```

**state/auth.json 缓存格式**（fetch-endpoints 期望）：

```json
{ "duoke": { "ok": true, "creds": { "key": "<token>", "lang": "chs", "version": "" }, "harvested_at": "<ISO时间>" } }
```

**多客 IndexedDB 细节（2026-10-08实测仍有效）**：key 存于 IndexedDB `keyval-store` 库 `keyval` 表的 `duoke:app` 键（zustand persist 结构、双重JSON序列化，取 `state.token`）。cdp-eval 的表达式须用 async IIFE（Runtime.evaluate 对返回 Promise 需 awaitPromise，本脚本项目前为 false——如取不到改用 harvest-auth.mjs 的网络监听回落路径：导航种子页被动等带 key 的请求）。

## 附B：浏览器UI兜底采集（直连整系统失败/接口改版排查时使用）

> 直连化之前的原主路径，全部保留可用。特点：零凭据接触、零风控暴露，但比直连慢得多（约15秒/页）。
> 翻页/筛选/取数均可用裸 CDP（cdp-eval.mjs / capture-pages.mjs）以最方便的方式驱动（如直接调分页组件、读表格数据），不必拘泥于纯UI点击；**只读红线不变**。

**前置（必做）**：`node scripts/check-login.mjs`（铁律②③：实际校验，不可凭记忆）；脚本自动拉起窗口并开两系统页面；窗口连不上 → 告知用户启动比特浏览器后终止。未登录 → 【登录阻断流程】（硬停+零数据回答，只通知登录，见 SKILL.md）。

**AI 看页面的方式（V1.8 起，替代 take_snapshot/list_network_requests）**：

```bash
node scripts/cdp-eval.mjs --list                                            # 列出窗口所有标签页
node scripts/cdp-eval.mjs --system yizhe --url '<endpoint.page>' --js 'document.body.innerText.slice(0,2000)'   # 看页面文本
node scripts/cdp-eval.mjs --system yizhe --js 'JSON.stringify([...document.querySelectorAll(".ant-pagination li")].map(e=>e.innerText))'   # 查分页器结构
node scripts/cdp-eval.mjs --system yizhe --js 'performance.getEntriesByType("resource").filter(e=>e.name.includes("api.yizheyun.com")).map(e=>e.name).slice(-10)'   # 看页面自己发过的API请求（被动观测）
```

**模式A · 首屏收割（V1.8 CDP版）**：cdp-eval 导航到 endpoint.page → 等待 wait_text 出现（`--js 'document.body.innerText.includes("<wait_text>")'`）→ 被动观测法拿请求：页面请求完成后用 `performance.getEntriesByType("resource")` 匹配 endpoint.api；需要响应体时优先直读页面数据（SPA 的数据通常已在内存/表格里：`--js 'JSON.stringify(window.__store?.state || 表格数据)'` 探查），或改走直连路径修复。

**模式B · 翻页收割**（endpoint.mode 含 B）——默认走 B-CDP 收割器，失败回落 B-CDP手动：
前置（通用）：cdp-eval 导航到 endpoint.page → 把「每页条数」调到最大（衣者antd分页器：读分页器结构 → 模拟选择100条/页——**UI下拉交互裸CDP较繁琐，优先直接调组件状态或接受默认页数**；多客上限20条/页）→ 按模式A收割**第1页**。

【B-CDP · 收割器翻页（约1-2秒/页，不变）】第2页起执行：
```
node scripts/capture-pages.mjs --api <endpoint.api> --file data/raw/<日期>/<槽>/<endpoint.file> --list-path <endpoint.list_path> --match-url <endpoint.page> --max-pages <50>
```
- 末行输出JSON摘要（ok/pages/rows/reason）——与页面「共搜索到N条」做行数校验
- ok=false / 行数对不上 / 连不上调试端口 → **回落 cdp-eval 手动逐页**，并记入 capture-issues
- 前提：采集窗口在线（bit.mjs 自动发现端口；capture-pages.mjs 自身的端口发现逻辑与 harvest-auth 一致，V1.8 已兼容比特随机端口）

【B-CDP手动 · cdp-eval 逐页翻页（原B-MCP回落模式的替代）】：
a. cdp-eval 读分页器/列表状态定位「下一页」按钮（选择器/文本）
b. 精确等待：驱动翻页（`--js` 内 `document.querySelector('.ant-pagination-next').click()`——属翻页驱动，铁律允许）→ 等**页码/区间文本变化**（如「第 101-200 条」），不用固定sleep
c. 选择器复用：列表重渲染后分页器选择器通常稳定；失效 → 重读 DOM 结构重新定位
d. 批量收割：可连翻2-3页再一次统一读取表格数据（`--js` 直接序列化表格行），按「行数 vs UI总数」校验
e. 循环直到「下一页」禁用/消失或到达 endpoint.max_pages（默认50页/次，防无限采集）

**模式B' · 筛选收割**（增量端点需按时间/状态分批时）：cdp-eval 读筛选控件结构 → 驱动设置（React 受控组件须原生 setter+input事件——参考既有脚本写法）→ 触发查询 → 等待 → 收割 → 恢复筛选条件。

**降级模式C · 文本兜底**：A/B均失败时，cdp-eval 直接序列化表格文本落盘（`--out 表格快照.txt`，首行加 `{"_mode":"snapshot"}` 标记）。

## 落盘规范（ingest.mjs 依赖，与直连路径一致）

- `.json` 文件 = 接口响应体**原文**（保留 code/msg/err 外层）
- `.jsonl` 文件 = 按 endpoint 的 `list_path` 提取数组，每行一个对象（提取动作发生在本地文件处理，不是页面内）
- 目录 `data/raw/<YYYY-MM-DD>/<am|pm>/`，文件名 = endpoint.file；每页收割的数组**追加**到同一 jsonl

**校验三板斧（兜底路径专用；直连路径由脚本内置校验替代）**：①行数 vs UI「共搜索到 N / 总计 N」②金额合计 vs UI「统计」栏③抽样首行字段 vs UI 首行。全部对平才算完整。

## ⚠️ 实测环境事实（2026-09-24 首轮实测 + 2026-11-05 比特浏览器版增补，兜底路径直接照做勿再排查）

1. **比特窗口 CDP 端口是动态的**：每次 open 端口不同（已实测 61877→63520→63663→64303），**任何脚本/配置不得硬编码端口**——统一经 bit.mjs / harvest-auth 发现（`/browser/ports` 或幂等 open 返回）。
2. **衣者登录跳转是 SPA 客户端路由**：未登录访问业务页先短暂呈现业务页 URL 再跳登录页（V1.8.1 实测教训）——登录判定**必须以 storage 凭据为真值**（check-login.mjs 已实现），只看 URL/快照会误判"已登录"。
3. **多客分页上限 20 条/页**（无100选项）：约450款≈23页。多客带搜索图标的 Select 可驱动过滤，纯分页器只能点击。
4. **衣者库存 total 口径**：`total` 含零库存已下单款，`list` 只返回有库存款（实测 1273 款=12×100+73，出现空页即到尾）。**不要**为凑 total 反复翻页（直连路径已按 total_relaxed 处理）。
5. **导出按钮是只读红线禁区**：多客/衣者的「导出」属写入类操作（铁律⑤），**未获用户明确放开前禁止点击**。
6. **比特浏览器指纹**：suyi 窗口为 Windows/Chrome 147 指纹（平台伪装），衣者/多客视为一台 Windows 电脑——正常现象，勿在排查"UA是Windows"上浪费时间；勿随意 randomize 指纹（会触发两系统风控重新验证）。
7. **比特 API key 单一来源**：`~/.workbuddy/mcp.json` 的 bitbrowser.headers.x-api-key（bit.mjs 自动读取，脚本无需再配）；Token 在比特客户端重新生成后只需更新该文件。 historic：2026-11-05 曾因终端脱敏显示误判 key 失效、把脱敏假值写入 mcp.json——**key 排障以"用文件里的 key 实际调 API"为准，不信终端回显**。
8. **多浏览器并存**：比特里另有 001~009 海外代理窗口（socks5 美国线路），**严禁复用**——衣者/多客走美国 IP 大概率触发风控；采集只碰 suyi 窗口。
