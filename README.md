# suyi-scm-collector 使用说明（部署与操作手册）

> 衣者 × 多客 数据采集与经营日报智能体技能
> 版本 V1.6 ｜ 更新 2026-11-05 ｜ 配套文档：《PRD》《SOP》《技术方案》（见项目 docs/ 目录）

## 运行环境与数据目录（V1.6 起必读）

- **平台**：Mac / Windows 均可运行（Node ≥ 18、Python3 + openpyxl）。脚本全部动态解析路径，无需修改任何代码即可部署
- **代码目录**：skill 安装目录（含 SKILL.md / scripts / config / references），运行不会在其中产生数据
- **数据目录**：默认 `~/WorkBuddy/scm-collector-data/`（用户主目录下），可用环境变量 `SCM_DATA_HOME` 指定其他位置；`state/`、`data/`、`out/` 三个子目录由脚本自动创建
- 本文档中提到的 `out/...`、`state/...`、`data/raw/...` 路径均指**数据目录**下的相对路径

---

## 一、这是什么

一套部署在**客户现场专用电脑**上的智能体技能（Skill），从两个互不相通的 SaaS 系统**只读采集**数据，自动生成经营日报、预警清单和数据看板：

**采集方式（2026-09-24 直连化改造）**：脚本以机器速度**直调两系统的只读查询接口**（晚间全量批次约1-2分钟）。登录态由专用 Chrome 浏览器维持——每轮采集前脚本经调试端口从浏览器**实时收割会话凭据**（衣者token/多客key），全程不接触账号密码、不自动登录；直连失败时自动回落浏览器UI采集兜底。

- **衣者**（scm.yizheyun.com）——研发生产：样板、跟单、生产进度、财务
- **多客**（air.duoke.net）——销售库存：商品SKU、销售单据、收支流水、客户

核心价值：打通两系统数据、**留存每日库存快照（多客本身不存历史）**、替代人工统计、补货预警自动计算与留存。

## 二、功能总览

| 功能 | 说明 | 产出 |
|------|------|------|
| 早晚双快照 | 每天 08:30 / 18:30 全量抄录多客 SKU 级库存 + 衣者款级库存，永久留存 | `data/raw/<日期>/<am\|pm>/` |
| 经营日报 | 老板汇总版 + 研发/生产/销售/财务/仓库五部门分版 | `out/日报-<日期>*.txt`，08:30 批次生成 |
| 实时预警 | 生产异常（复用衣者预警阈值）+ 补货预警 + 超期订单，每小时轮询 | 落盘 `out/alerts-*.json`，进日报预警板块 |
| 款号映射 | 衣者款号 ↔ 多客货号自动匹配（全等→辅助→人工队列） | `state/mapping.json`、`out/款号核对清单-<日期>.md` |
| 每日对账 | 成本口径（±1元，以多客为准）、入库一致性、匹配率 | `out/reconcile-<日期>.json`，异常进日报附注 |
| 数据看板 | 当日经营看板（现场电脑浏览器打开） | `out/看板-<日期>.html` |

## 三、环境要求

| 项 | 要求 |
|----|------|
| 机器 | 客户现场 Windows 专用机，**常开机不断电**（采集登录态在这台机器上） |
| Node.js | 22+（脚本零第三方依赖，只需 Node 本体） |
| 浏览器 | **比特浏览器客户端（≥7.1.5）**，专用窗口 `suyi`（无代理直连），只跑采集不办公；客户端保持运行（Local API 54345） |
| 智能体 | WorkBuddy（或其他支持 Skill + MCP 的智能体），已装 bitbrowser MCP |
| 账号 | 衣者：管理账号（账号密码登录）；多客：黑端账号（手机 APP「我的→扫一扫」扫码登录） |

## 四、首次部署（照着一步步做）

### 步骤 1：安装 Node.js 22

1. 打开 https://nodejs.org ，下载 **22.x LTS** 的 Windows 安装包，一路默认下一步装完
2. 验证：按 `Win+R` 输入 `cmd` 回车，在黑窗口里输入 `node -v`，显示 `v22.x.x` 即成功

### 步骤 2：放置技能目录

1. 把整个 `suyi-scm-collector` 文件夹复制到现场机，例如 `D:\suyi-scm-collector`
2. 再复制一份到 WorkBuddy 的技能目录：`C:\Users\你的用户名\.workbuddy\skills\suyi-scm-collector\`（没有 `skills` 文件夹就新建一个；确切路径以所用 WorkBuddy 版本的说明为准）
3. 验证链路（在 `D:\suyi-scm-collector` 这份上测，命令逐行执行）：
   ```
   cd /d D:\suyi-scm-collector
   node scripts\mock-capture.mjs --slot am
   node scripts\ingest.mjs --slot am
   node scripts\match-template-no.mjs
   node scripts\alert-rules.mjs
   node scripts\reconcile.mjs
   node scripts\report-daily.mjs
   ```
   在 `out\` 里看到今天的「日报-….md」即链路正常。这是模拟数据自测，测完把 `data\`、`state\`、`out\` 三个文件夹删掉，从干净状态开始正式使用

### 步骤 3：安装比特浏览器、建采集窗口并登录两个系统

1. 安装比特浏览器客户端（≥7.1.5，https://www.bitbrowser.cn ），注册/登录后保持运行
2. 客户端里创建浏览器窗口：名称填 **`suyi`**（精确一致，脚本按名定位），代理选「**不使用代理**」（noproxy 直连；严禁挂海外代理——衣者/多客会触发风控）
3. 打开这个窗口，登录衣者：地址栏输入 `scm.yizheyun.com` → 输入账号密码登录 → 看到顶栏「员工 XXX」即成功
4. 登录多客：地址栏输入 `air.duoke.net` → 屏幕出现二维码 → 手机打开多客 APP →「我的」页往下滑 →「扫一扫」→ 扫屏幕上的码 → 进入黑端后台即成功
5. **从此这个窗口只跑采集**：不用它办公、绝不点「退出登录」、不复用为其他账号窗口（登录态会保留在窗口 Profile 里）

### 步骤 4：配置 WorkBuddy 与比特 MCP

1. 比特客户端「系统设置 → Local API」→ 开启**鉴权控制** → 复制 API Token
2. 在 WorkBuddy 的 `mcp.json`（`C:\Users\你的用户名\.workbuddy\mcp.json`）写入（**必须在 mcpServers 字段内**）：
   ```json
   {
     "mcpServers": {
       "bitbrowser": {
         "url": "http://127.0.0.1:54345/mcp",
         "headers": { "x-api-key": "<粘贴你的Token>" }
       }
     }
   }
   ```
   然后在连接器管理页对 bitbrowser 点「信任」。Token 只此一份来源，skill 脚本自动读取该文件；比特重新生成 Token 后只需更新此文件。
3. 确认技能已放入 skills 目录（见步骤 2）
4. 验证：对 WorkBuddy 说 **「检查登录状态」**——智能体会执行 `node scripts\check-login.mjs`（自动拉起窗口+校验登录态），应回答两个系统均已登录

### 步骤 5：首跑（部署首跑批次）

对智能体说：

> 跑采集——部署首跑，包含 onetime 端点

首跑做三件事：①跑通全链路（直连采集约2分钟）；②落地预警阈值等一次性配置；③**校验标注[待实测]的端点**（直连请求参数/多客URL形态等）——对不上的会被自动修正进 `endpoints.json` 并记录变更，这是正常的自愈行为。

看到这些算成功：

- `data\raw\今天\am\` 下出现约 30 个采集文件
- `out\` 下出现日报、五部门分版和看板 HTML
- 数量校验如有出入，会记录在 `state\capture-issues.jsonl` 并在日报附注中说明——不会静默丢弃

### 步骤 6：配置定时任务（WorkBuddy）

WorkBuddy 的定时任务本质是「**到点自动把一段提示词发给智能体**」，所以每个任务只需要配三样东西：任务名、触发时间、提示词。

操作：打开 WorkBuddy → 找到「定时任务」入口（部分版本叫「自动化」，一般在侧边栏或工作台）→ 新建任务 → 按下表逐个添加（5 个定时 + 1 个手动；午间批次可选，先不配也行）：

| # | 任务名（自定） | 触发时间 | 提示词（原样复制粘贴进定时任务） |
|---|------|------|------|
| 1 | 早间采集+日报 | 每天 08:30 | 跑采集——早间批次（poll+morning端点+订单流水昨日增量），生成今日日报。 |
| 2 | 午间进度（可选） | 每天 12:30 | 执行午间批次：采集在产类明细（跟单/生产订单/采购/待入库）。 |
| 3 | 晚间全量+对账 | 每天 18:30 | 跑采集——晚间批次（全量：库存快照+明细+当日订单流水），完成后执行每日对账，异常写入日报附注。 |
| 4 | 预警轮询 | 每小时 | 执行预警轮询批次：只采集poll端点并运行预警计算，命中即生成预警清单并在对话中摘要，无命中则简短报告一句。 |
| 5 | 周一维度刷新 | 每周一 07:00 | 执行周一批次：采集weekly端点并全量回捞样板列表。 |
| 6 | 部署首跑 | 不用建定时 | 手动说一次即可（步骤 5 已做）。 |

配置要点：

- 提示词里的批次名与 SKILL.md「批次与采集范围」一一对应，智能体靠它判断这一轮该采哪些端点——**提示词照抄，别自行改写**
- 轮询默认每小时；WorkBuddy 免费额度紧张就改成每 2 小时，同时把该任务的触发间隔改成每 2 小时保持口径一致
- 定时按机器本地时间触发，先确认现场机时间准确（设置 → 时间和语言 → 自动设置时间）

**怎么确认定时任务真的在跑**（配完第二天早上检查这三样）：

1. `out\日报-今天.md` 的文件修改时间应落在 08:30~09:00 之间
2. `state\watermark.json` 里的 `last_success_date` 应等于今天
3. 对智能体说「出日报」，能立刻呈现今日日报

没触发时的排查顺序：WorkBuddy 是否开机自启并保持登录 → 任务开关是否打开 → 手动把提示词发一遍，验证提示词本身能跑通。

### 步骤 7：验收第一周

- [ ] 08:30 日报连续 3 天按时生成
- [ ] 18:30 对账有产出，异常有披露
- [ ] 预警轮询能产出预警清单（验证方法：临时把 `rules.json` 的 `预警阈值天` 改大制造一条命中，在 `out\alerts-*.json` 看到产出后改回 20）
- [ ] 周一 07:00 维度任务有执行（`data\raw\周一的日期\` 下出现 weekly 类文件）
- [ ] 连续 14 天稳定运行 = 达到 M1 验收口径

## 五、日常使用

### 对智能体说话（触发词）

| 你说 | 发生什么 |
|------|----------|
| 「跑采集」 | 执行一轮当前时段批次直连采集 + 全链路处理 |
| 「出日报」 | 基于已采数据重新生成日报 |
| 「看库存」 | 呈现当前快照库存摘要 |
| 「检查登录状态」 | 收割凭据并各发一个只读探测请求，报告登录态 |
| 「继续」 | 登录后恢复采集（见下） |

### 登录失效时（会碰到，正常现象）

1. 智能体在对话中提示「XX系统未登录」，本次流程已停止
2. **你要做**：到现场机打开比特浏览器的 suyi 窗口（客户端「打开」；智能体跑采集时也会自动拉起该窗口），完成登录（衣者账密 / 多客手机扫码）
3. 回来对智能体说 **「继续」**——它会重新收割凭据后从断点续采，不会重采已完成的
4. 登录态由浏览器Profile维持，通常数天~数周失效一次；具体有效期以实测为准

### 款号人工核对（不定期）

1. 新款无法自动匹配时，`out/款号核对清单-<日期>.md` 列出待确认项
2. **你要做**：在对话中回复确认，例如：「SK263967 对应 SM263967，确认」
3. 智能体回写映射表，同款后续自动命中

### 看数据看板

现场电脑浏览器直接打开 `out/看板-<日期>.html`（可投电视大屏）。手机公网访问是 P1 功能，当前版本不支持。

## 六、目录结构与配置

```
suyi-scm-collector/
├── SKILL.md            ← 智能体执行的操作规程（铁律、批次、采集流程）
├── README.md           ← 本文档
├── scripts/
│   ├── fetch-endpoints.mjs   直连采集器（默认采集路径：收割凭据→直调只读API→分页落盘）
│   ├── harvest-auth.mjs      凭据收割器（CDP实时收割衣者token/多客key；--check验证登录态）
│   ├── capture-pages.mjs     CDP翻页收割器（浏览器UI兜底采集时用；仅DOM/Input/Network域）
│   ├── mock-capture.mjs      Demo模拟数据（仅当你明确说"demo"时用）
│   ├── ingest.mjs            原始数据→state/db.json（按日期/早晚分槽）
│   ├── match-template-no.mjs 款号映射（全等→辅助→人工队列）
│   ├── alert-rules.mjs       预警计算（补货/超期）
│   ├── reconcile.mjs         每日对账
│   └── report-daily.mjs      日报+五部门分版+看板HTML
├── config/
│   ├── endpoints.json       采集注册表：30个端点+直连请求参数+tier批次分层（源系统改版时自愈更新）
│   └── rules.json           业务参数（下表）
├── state/              ← 运行时生成：db.json汇总库、watermark水位、auth.json凭据缓存、mapping映射、问题清单
├── data/raw/           ← 运行时生成：按日期/早晚槽留存的响应原文（库存历史就靠它）
└── out/                ← 运行时生成：日报/看板/预警/对账产出
```

### rules.json 常调参数

| 参数 | 默认 | 说明 |
|------|------|------|
| 补货预警.面料采购周期天 / 生产周期天 | 15 / 5 | 待供应商/工厂实测数据校准 |
| 补货预警.安全系数 / 预警阈值天 | 1.2 / 20 | 建议补货量与触发线 |
| 补货预警.快款生命周期天 | 45 | 超期未动销进滞销清单 |
| 对账规则.成本差异容忍元 | 1 | 超差出清单 |
| 对账规则.入库一致性告警阈值 | 0.005 | 差异率超 0.5% 告警 |
| 款号映射.目标匹配率 | 0.98 | M1 期基线 95%，M2 起 98% |
| 直连采集.请求间隔毫秒 | 300 | 出枪节奏：相邻请求最小间隔=本值/并发数（等待不占并发槽）；出现风控迹象时调大 |
| 直连采集.并发数 | 3 | 同时在途的请求数（全端点并发+端点内并发翻页，请求级信号量限流；源系统页面本身就并发数十XHR） |
| 直连采集.单端点最大页数 / 请求超时毫秒 | 300 / 30000 | 防无限翻页与卡死 |
| 直连采集.凭据缓存有效期小时 | 12 | CDP收割失败时允许使用缓存凭据的时限 |

## 七、手动执行命令（调试用）

```bash
cd suyi-scm-collector
node scripts/harvest-auth.mjs --check                 # 检查两系统登录态
node scripts/fetch-endpoints.mjs --batch evening      # 直连采集（batch可选morning/noon/evening/poll/weekly/first）
node scripts/fetch-endpoints.mjs --batch evening --dry-run   # 只打印将发出的请求，不实际采集
node scripts/ingest.mjs --date 2026-09-25 --slot am
node scripts/match-template-no.mjs
node scripts/alert-rules.mjs --date 2026-09-25
node scripts/reconcile.mjs --date 2026-09-25
node scripts/report-daily.mjs --date 2026-09-25
node scripts/mock-capture.mjs --date 2026-09-25 --slot am   # 仅demo（槽位有数据时自动隔离）
```
`--date` 缺省为今天；`--slot` 缺省按时钟推断（14点后=pm）；`--batch` 缺省按时段推断（am=早间/pm=晚间）。参数支持 `--flag value` 和 `--flag=value` 两种写法。

## 八、常见问题

| 现象 | 处置 |
|------|------|
| 日报没按时生成 | 依次查：①浏览器是否登录失效（最常见）②WorkBuddy 定时任务是否在跑。产出永远会先落盘 `out/`，随时可重新生成 |
| 提示「未登录」 | 见「登录失效」流程；**系统不会自动登录、不会绕过认证** |
| 日报里出现「数据截至XX:XX」 | 当日有采集异常，系统降级沿用最近快照并如实标注——这是设计行为，不是故障 |
| 数据对不上/缺项 | 查 `state/capture-issues.jsonl`（所有数据质量问题都记录在案，绝不静默丢弃） |
| 提示「未发现任何Chrome DevTools端口」 | 比特客户端未运行或采集窗口未拉起——启动比特客户端后对智能体说「跑采集」（脚本自动拉起 suyi 窗口）；仍不行按 SKILL.md 采集兜底.md 附A五步排查 |
| 比特报「token 失效/Login out」 | 比特客户端「系统设置→Local API」重新复制 Token，更新 mcp.json 的 bitbrowser.headers.x-api-key |
| 个别接口直连失败 | 自动记入 capture-issues 并继续其余端点，日报披露缺项；智能体按报错自愈更新 `endpoints.json` 后下轮恢复 |
| 直连整系统失败（批量报错/改版） | 智能体自动回落浏览器UI采集（cdp-eval）保日报，同时探查新接口自愈更新 `endpoints.json`（变更记入 `_comment`） |
| 想看模拟效果 | 明确说「demo」或「模拟数据」才会触发，产物自动隔离到 `_quarantine_mock/`，不会污染真实数据 |

## 九、红线（违反会破坏整个设计）

1. **直连仅限只读查询**——脚本只调用 `endpoints.json` 注册的查询类接口；保存/新建/删除/导入导出类接口与按钮**一律禁止**（导出按钮同样不许点）
2. **只读红线（含页内脚本）**——evaluate_script 等页内脚本已于 2026-09-25 解禁、可自由用于翻页/取数等方便用途；但保存/删除/导出/提交类写操作，无论 UI 点击还是脚本执行，一律禁止
