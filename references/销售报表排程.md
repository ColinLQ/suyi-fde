# 销售报表：定时任务 vs 按需索取（2026-10-10 建）

> 数据链路：多客3年订单（全量+明细行） + 客户档案 + 实时库存 + 衣者当前库存 → 客户账户合并(同人归并) → V2报表
> 脚本均在 skill `scripts/` 下；参数在 `config/sales-params.json`（拍板后改配置自动生效，无需改代码）。

## 一、适合定时任务的数据（数据源稳定、口径已定、无待拍板依赖）

| # | 数据 | 建议频率 | 触发词（对 WorkBuddy 说） | 产出 |
|---|---|---|---|---|
| A1 | **客户流失预警名单**（30-60天/60天-1年/1-2年三档，含下单/退单数、购买/退货金额、客单价、件单价） | **每日**（业务要求每天推） | `跑销售日报` | 报告§三 + JSON完整名单 |
| A2 | **新客15天/1月未复购名单**（第二单转化关键期） | 每日 | 同上 | 报告§3-4 |
| A3 | **日/周/月下单回款总览**（连带率、新老客购买单数/金额/连带、补单金额） | 每日 | 同上 | 报告§一 |
| A4 | **导购业绩**（新老客金额、补单金额、老客占比） | 每日或每周一 | 同上 | 报告§五 |
| A5 | **款级动销**（周/半月/月三窗、全品类TOP30、单品类TOP10、含实时库存） | 每日（晚间快照后） | 同上 | 报告§六 |
| A6 | **售罄率TOP15**（近30日销量÷衣者当前库存；系统方加"总进货数"字段后自动切分母） | 每日 | 同上 | 报告§6-6 |
| A7 | **新品上市一周/一月 + 累计客户数TOP10**（按多客建档日≈上市） | 每日 | 同上 | 报告§6-7/6-8 |
| A8 | **库存积压/告急/预售欠货**（当年当季、周月销量、周转周） | 每日 | 同上 | 报告§九 |
| A9 | **补单金额TOP**（客户行为口径） | 每日 | 同上 | 报告§七 |
| A10 | **新客户月度分析**（首单时间/客单价/件单价） | 每日 | 同上 | 报告§八 |
| A11 | **客户账户合并审计表**（同人归并明细，供业务核对） | 每周一（客户档案周采后） | `重建客户合并组` | 审计表MD |
| A12 | **老客盘活名单**（超3个月~2年，含首单时间，按历史净额） | 随每日日报自动更新，**无需单独触发**（报告§3-6 Top30 + JSON完整名单 revive_90up） | 临时只要这张名单时说：`出老客盘活名单`（直接读当日JSON提取，秒回，不重跑采集） | 报告§3-6 + JSON |

**一条命令全覆盖**：`跑销售日报` = 增量刷单 + V2报表 + 看板。定时任务只需建这一个（或再加周一合并组重建）。

## 二、需每次单独索取的数据（有前提条件或人工判断）

| # | 数据 | 为什么不能全自动 | 怎么要 |
|---|---|---|---|
| B1 | **保本款/亏本款/利润款分析**【需求12】 | 依赖月度成本核算（财务口径：窗口重定向采集+动销拼接+SKU成本加权），月度跑一次较重 | 月初说：`核算上月成本 + 出保本亏本款分析` |
| B2 | **上市时间×动销（天气/市场）归因**【需求13】 | 需气温数据接入+企划复盘框架，属专项分析 | 说：`做上市动销与天气匹配分析` |
| B3 | **3年订单全量重采/回填** | 约1小时，日常增量即可，仅初次或数据损坏时跑 | 说：`重采3年订单全量` |
| B4 | **合并组拆分重算** | 需人工确认"同名不同人"后指定组号 | 说：`拆开合并组G123，重算报表` |
| B5 | **自定义口径临时表**（如某客户全史、某款全链路、某导购明细） | 一次性问题 | 直接描述需求 |
| B6 | **历史某天的报表回溯** | 需指定日期（数据都在，随时可回放） | 说：`出2026-09-30的销售报表` |

## 三、定时任务配置方法（WorkBuddy 自动化）

在 WorkBuddy 里对我说（一次性）：
- `每天 18:40 帮我跑销售日报`（≈晚间快照后：增量刷单→V2报表→看板；次晨还能看到）
- `每周一 09:00 跑销售日报并重建客户合并组`

或手动建：设置→自动化→新建→时间选每天→提示词填：
```
@skill:scm-collector 跑销售日报：refresh-recent增量刷单 → build-sales-report-v2 → build-sales-dashboard-v2，完成后把看板路径发我
```

**登录态是唯一硬前提**：定时任务跑到检测未登录时，会硬停并企微+对话双通道提醒"多客/衣者未登录，请登录后说继续"，不会拿旧数据冒充。

## 四、脚本命令速查（skill 根目录执行，Node 22）

```bash
node scripts/refresh-recent.mjs            # 增量：近20日订单列表+新单明细（约1-3分钟）
node scripts/build-dedup-groups.mjs        # 重建客户账户合并组（周一或客户档案更新后）
node scripts/build-sales-report-v2.mjs     # V2报表（MD+JSON）→ out/销售数据报告-<当日>.md
node scripts/build-sales-dashboard-v2.mjs  # 看板HTML → out/销售数据看板-<当日>.html
node scripts/fetch-sales-orders.mjs list   # 3年订单全量重采（B3，约1小时）
node scripts/fetch-sales-orders.mjs detail # 全量明细回填（断点续传，并发6）
node scripts/audit-client-counts.mjs       # 合并口径影响审计
```

## 五、待拍板参数（拍板后改 config/sales-params.json）

| 参数 | 现值 | 状态 |
