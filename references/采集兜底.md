# 采集兜底手册（直连失败时才读）

> 适用场景：直连采集整系统失败（批量404/结构变化/持续超时）、收割器连不上浏览器调试端口、或需要排查接口改版。日常主路径是直连，**不要**为提速走本手册。

## 附A：MCP请求文件导入兜底（收割器连不上调试端口时）

> 适用：fetch 报「未发现任何Chrome DevTools端口」（浏览器以pipe模式启动/调试端口被拦截），但 MCP 本身能正常控制浏览器。凭据不经对话流转，全程走文件。

```
1. 确认第0步已用MCP打开两系统页面（sample-management/list 与 goods/list），页面已加载出数据
2. list_network_requests(pageId) → 各找一个 api.yizheyun.com 的请求与一个 api.duoke.net 的请求，记下 reqid
3. get_network_request(reqid, requestFilePath=<临时目录>/yizhe.network-request)（多客同理存 duoke.network-request）
4. node scripts/harvest-auth.mjs --import <临时目录>   # 深度扫描请求文件，提取token/key写入 state/auth.json
5. 重跑第1步 fetch（脚本收割仍不可达时会自动使用刚写入的缓存）
```

**多客key的补充手段（2026-10-08实测）**：多客新版前端 localStorage 为空，key 存于 **IndexedDB `keyval-store` 库 `keyval` 表的 `duoke:app` 键**（zustand persist 结构、双重JSON序列化，取 `state.token`）。若附A导入的请求文件里没带key参数（GET查询串可能省略），用 evaluate_script 读 IndexedDB 落临时文件后，按下述结构写入 `state/auth.json`（fetch-endpoints 期望的缓存格式）：

```json
{ "duoke": { "ok": true, "creds": { "key": "<token>", "lang": "chs", "version": "" }, "harvested_at": "<ISO时间>" } }
```

注意 MCP 落盘根是 `/private/var/...`（即 $TMPDIR 的真实路径前缀），shell 读取时用 `/private/var` 开头。

## 附B：浏览器UI兜底采集（直连整系统失败/接口改版排查时使用）

> 直连化之前的原主路径，全部保留可用。特点：零凭据接触、零风控暴露，但比直连慢得多（约15秒/页）。
> 2026-09-25 代码注入禁令解除后：翻页/筛选/取数均可用 `evaluate_script` 或 CDP `Runtime.evaluate` 以最方便的方式驱动（如直接调分页组件、读表格数据），不必拘泥于纯UI点击；**只读红线不变**。

**前置（必做）**：调用 `mcp__chrome-devtools__list_pages` 实际检查浏览器（铁律③）；无相关页面则 `new_page` 打开 endpoints.json 的 `base_page`；连不上则告知用户启动浏览器后终止。逐系统登录检测：navigate 到 `login_check.page` → take_snapshot → 出现密码框/登录按钮且无业务菜单/url含login = 未登录 → 【登录阻断流程】（硬停+零数据回答，只通知登录，见 SKILL.md）。

**模式A · 首屏收割**：navigate_page → endpoint.page → wait_for(wait_text) → list_network_requests 匹配 endpoint.api → get_network_request(reqid, responseFilePath=落盘路径)。

**模式B · 翻页收割**（endpoint.mode 含 B）——默认走 B-CDP 收割器，失败回落 B-MCP：
前置（两种模式通用）：导航到 endpoint.page → 把「每页条数」调到最大（衣者antd分页器：click 分页器 combobox → 连按3次 ArrowDown → Enter=100条/页，中途勿插snapshot；多客上限20条/页）→ 按模式A收割**第1页**。

【B-CDP · 收割器翻页（约1-2秒/页）】第2页起执行：
```
node scripts/capture-pages.mjs --api <endpoint.api> --file data/raw/<日期>/<槽>/<endpoint.file> --list-path <endpoint.list_path> --match-url <endpoint.page> --max-pages <50>
```
- 末行输出JSON摘要（ok/pages/rows/reason）——与页面「共搜索到N条」做行数校验
- ok=false / 行数对不上 / 连不上调试端口 → **回落 B-MCP** 采剩余页，并记入 capture-issues
- 前提：Chrome 以 `--remote-debugging-port=9222` 启动（间隔等参数见 rules.json「CDP兜底收割」）

【B-MCP · 纯UI逐页翻页（回落模式）】：
a. take_snapshot → 定位"下一页"按钮uid（下一页 / > / Next；antd分页 li.next）
b. 精确等待：click(uid) → wait_for **页码/区间文本变化**（如「第 101-200 条」或页码数字），不用固定sleep
c. uid 复用：循环内不重复 take_snapshot（列表重渲染后分页按钮uid通常稳定）；click 失败/元素失效 → 重拍一次快照重新定位（兜底分支）
d. 批量收割：可连点2-3页再一次 list_network_requests 统一收割，按「endpoint.api 的URL + 时间序取最新未收割」匹配
e. 循环直到"下一页"禁用/消失或到达 endpoint.max_pages（默认50页/次，防无限采集）

**模式B' · 筛选收割**（增量端点需按时间/状态分批时）：take_snapshot 定位筛选控件 → fill/click 设置 → 点击"搜索/查询" → wait_for → 收割响应 → 恢复筛选条件。

**降级模式C · 快照兜底**：A/B均失败时，直接 take_snapshot 解析表格文本落盘（首行加 `{"_mode":"snapshot"}` 标记）。

## 落盘规范（ingest.mjs 依赖，与直连路径一致）

- `.json` 文件 = 接口响应体**原文**（保留 code/msg/err 外层）
- `.jsonl` 文件 = 按 endpoint 的 `list_path` 提取数组，每行一个对象（提取动作发生在本地文件处理，不是页面内）
- 目录 `data/raw/<YYYY-MM-DD>/<am|pm>/`，文件名 = endpoint.file；每页收割的数组**追加**到同一 jsonl

**校验三板斧（兜底路径专用；直连路径由脚本内置校验替代）**：①行数 vs UI「共搜索到 N / 总计 N」②金额合计 vs UI「统计」栏③抽样首行字段 vs UI 首行。全部对平才算完整。

## ⚠️ 实测环境事实（2026-09-24 首轮实测 + 2026-10-08 增补，兜底路径直接照做勿再排查）

1. **MCP 落盘根**：chrome-devtools-mcp 若非本会话启动（未协商 workspace roots），`responseFilePath` 唯一可写根 = `os.tmpdir()`。绕行做法：先建 `$TMPDIR/scm-raw`，落盘后用 shell `cp` 回 `data/raw/<date>/<slot>/` 并改规范名。**目标态**：让 WorkBuddy 按 mcp.json 自行拉起 MCP（见README步骤4）后可直接写技能目录，此绕路消失。
2. **antd 分页器改每页条数**（listbox 选项不进 a11y 树，fill 无效）：`click` 分页器 combobox → 连按 3 次 `ArrowDown`（10→20→50→100）→ `Enter`。中间**不要插 snapshot**（会致下拉关闭回到10条/页）。
3. **多客分页上限 20 条/页**（无100选项）：约450款≈23页。多客带搜索图标的 Select 可 fill 过滤，纯分页器只能点击。
4. **翻页收割节奏**（约15秒/页）：click 下一页 → 等页码/区间文本变化 → `list_network_requests` 从末页索引找新请求 → `get_network_request` 落盘 → 追加 jsonl。reqid 大致递增可作找起点的参考，但**匹配以 URL+时间序为准，不做 reqid 算术**。
5. **衣者库存 total 口径**：`total` 含零库存已下单款，`list` 只返回有库存款（实测 1273 款=12×100+73，出现空页即到尾）。**不要**为凑 total 反复翻页（直连路径已按 total_relaxed 处理）。
6. **导出按钮是只读红线禁区**：多客/衣者的「导出」属写入类操作（铁律⑥、SOP §1），**未获用户明确放开前禁止点击**。
7. **（2026-10-08）WorkBuddy MCP 拉起的浏览器是 pipe 模式**：无 DevTools 调试端口，harvest 实时收割不可用——此时凭据缓存（state/auth.json）是主路径，按附A导入刷新缓存。
