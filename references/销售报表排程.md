# 销售报表：定时任务 vs 按需索取（V2.5 · 2026-10-12 定稿）

> 数据链路：多客3年订单全量+明细 → 客户账户合并 → 报表引擎(JSON) → Excel 39 sheet 嵌图交付
> 口径以 SKILL.md「销售数据报表（V2.5）」节为准（柳红三轮沟通逐表确认）；Excel 首个 sheet「00·口径说明」含全部口径速查。

## 定时任务（一条命令：`跑销售日报`，产出 Excel）

| 数据 | 频率 | 说明 |
|---|---|---|
| 日周月回款总览（连带/新老客/建单价/补单） | 每日 | |
| 月未下单（近3月有单+本月无单，含手机号/归属店铺） | 每日 | |
| 新客未复购（15-30/30-60档） | 每日 | |
| ABCD客户、新客户月度分析 | 每日 | |
| 复购款TOP30（周/半月/月，客户再购同一款口径） | 每日 | |
| 导购·昨日（按店铺） | 每日晨间（昨日数据） | 生成节奏即统计窗口 |
| 导购·上周（按店铺） | 周一晨间 | |
| 导购·本月截至昨日（按店铺） | 每日 | |
| 动销TOP30×3窗×2版本（全量/剔专属≥2客户） | 每日 | |
| 单品类TOP10×2版本、售罄率排行 | 每日 | |
| 新品上市三档（1-7/7-15/15-30天）+客户数TOP10（含实时库存） | 每日 | |
| 库存最大款/告急款（告急=库存<周销×2，当年当季） | 每日 | |
| 老客盘活名单（超3月~2年，手机号/归属店铺/首单时间） | 随日报自动更新 | |
| 客户流失预警三档 | 随日报 | |
| 客户账户合并审计表 | 每周一（客户档案周采后） | 触发词 `重建客户合并组` |

**建定时任务**：对我说 `每天 08:30 跑销售日报`（晨间，含昨日数据）；可加 `每周一 09:00 跑销售日报并重建客户合并组`。

## 按需索取

| 数据 | 触发词 | 原因 |
|---|---|---|
| 保本/亏本/利润款 | `核算上月成本+出保本亏本款分析` | 月度成本核算 |
| 上市×天气归因 | `做上市动销与天气匹配分析` | 需气温数据 |
| 3年订单全量重采 | `重采3年订单全量` | 约1小时 |
| 合并组拆分重算 | `拆开合并组G123，重算报表` | 需人工确认同名不同人 |
| 历史日期回溯 | `出2026-09-30的销售报表` | 数据都在 |
| 临时口径问题 | 直接问 | 一次性 |

## 脚本速查（skill 根目录）

```bash
node scripts/refresh-recent.mjs            # 增量刷单至当天（⚠️窗口已参数化，勿再硬编码）
node scripts/build-dedup-groups.mjs        # 合并组（周一）
node scripts/build-sales-report-v2.mjs     # 报表引擎 → 销售数据报告-<日期>.json
node scripts/fetch-goods-remarks.mjs      # 商品备注（缓存 state/goods-remarks.json，上市时间用）
node scripts/fetch-goods-pics.mjs          # 商品图（缓存 state/goods-pics/）
python3 scripts/build-sales-excel.py       # Excel 交付（39 sheet，需 openpyxl+Pillow）
node scripts/fetch-sales-orders.mjs list|detail  # 3年全量（重采用）
```
